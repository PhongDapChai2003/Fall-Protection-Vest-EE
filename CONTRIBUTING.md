# Contributing

Thanks for helping with the Fall Protection Vest Electrical Team project. Keep your changes small, clear, and easy for another student to review.

## Before starting

1. Check the Issues or team task list so two people do not unknowingly do the same job.
2. Update your local `main` branch.
3. Create a new branch for one task.

## Branch names

Use this pattern:

```text
area/short-task-name
```

Good examples:

- `firmware/read-bmi270`
- `algorithm/label-walking-data`
- `hardware/check-battery-current`
- `pcb/add-programming-header`
- `docs/week-3-meeting`
- `test/imu-bench-test`
- `fix/button-debounce`

## While working

- Do one main task per branch.
- Write down important test conditions and results.
- Do not commit passwords, API keys, personal information, or private research data.
- Do not connect a real inflation trigger without an approved test plan and supervision.
- Update your weekly progress file before opening a pull request.

## Commit messages

Write a short action statement:

```text
Add IMU serial data output
Fix battery voltage label
Document walking test setup
```

## Pull request checklist

- [ ] My branch has one clear purpose.
- [ ] I explained what I changed.
- [ ] I explained how I tested it.
- [ ] I included useful files, photos, plots, or results when needed.
- [ ] I did not include secrets or personal data.
- [ ] I updated documentation or weekly progress.
- [ ] I listed anything unfinished or unsafe to test.
- [ ] At least one teammate reviewed the work before merging.

## Simple review process

The reviewer checks that the change makes sense, can be followed, and does not create a safety problem. Questions are normal. Make the requested updates on the same branch, then ask the reviewer to look again. Merge only after the main concerns are handled.
